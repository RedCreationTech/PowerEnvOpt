# 电源动环 AI 智慧运维 v5 · 真实模型辅助、本地知识 Wiki

本项目是本机部署的业务验证原型：**模拟设备/工单数据 + 用户自行配置的真实模型 API + 独立可执行评测**。不接硬件、不训练专用模型、不自动控制设备；没有配置模型时，真实 AI 功能明确显示未配置，不用固定回复冒充成功。

## 快速启动

需要 Node.js 18 或更新版本。应用后端零第三方运行依赖。

```sh
npm start
```

打开终端显示的 `http://127.0.0.1:4173`。只绑定本机回环地址，不要经端口转发或公网反向代理共享。不要直接双击 `index.html` 来验证真实 AI，真实功能需要同源本地后端。

1. 在顶部身份下拉框切换为「林管理员」，进入「AI 接入设置」，先点击「读取服务端配置」，再选择 DeepSeek、通义千问 Qwen 或本地 OpenAI 兼容服务。
2. 按账号控制台填写模型名称、兼容接口 Base URL 与 API Key。密钥输入框不会回填已保存值，留空表示保留该提供商当前端点的密钥；两个云提供商各自保存配置，切换不会把一个提供商的密钥发给另一个。改变同一提供商的端点会清除其旧密钥，避免误发。
3. 分别填写并保存两家提供商的配置；再选择本次要使用的提供商并保存，明确点击「测试连接」。保存、启动、浏览页面均不自动调用模型；连接测试和每次 AI 操作可能产生供应商费用。
4. 切换「刘值班」在告警中心接管事件建单，再切换「周分析」，打开同一工单右侧详情的 AI 研判/知识页，使用真实 AI 诊断、建议方案、复测摘要或知识候选。模型结果需要人工采纳，不等于批准、执行、复测通过或关闭。
5. 在模型自测页面运行小样本烟测或完整冻结合成集。**尚未配置和运行的模型指标为「未验证」；不预填达标成绩。**

### 配置文件方式

`config.example.json` 是空密钥模板。也可先手动建立 `.runtime` 目录，将其复制为 `.runtime/config.json`，填写自己的配置再启动；POSIX 系统应设目录权限 700、文件权限 600。不要把填写后的文件提交 Git、贴进聊天、放入截图或分发压缩包。正常页面保存会使用限制权限写入服务器运行目录。

后端只返回提供商、模型、端点等非密钥配置以及 `hasKey` 状态。API Key 不写入前端脚本、localStorage、审计记录或 API 响应。`.runtime/` 已加入 `.gitignore`，静态服务器使用明确的前端资源白名单，不能下载运行配置或测试答案。此原型仍没有多用户认证，不适合共享服务器部署。

### 提供商

- DeepSeek：官方兼容接口 `https://api.deepseek.com`，默认模型名称仅为方便配置的起点，以账号当前支持的名称为准。[官方文档](https://api-docs.deepseek.com/)
- Qwen：按百炼账号地域填写 OpenAI 兼容 Base URL，例如中国内地常用 `https://dashscope.aliyuncs.com/compatible-mode/v1`。地域、模型与 Key 必须匹配。[兼容接口文档](https://www.alibabacloud.com/help/en/model-studio/compatibility-of-openai-with-dashscope)
- 本地模型：提供 OpenAI 兼容 `/chat/completions` 与 JSON 输出能力，Base URL 示例 `http://127.0.0.1:8000/v1`。后端允许回环端点；若将来需要局域网推理服务器，应先增加认证、网络隔离和明确的地址许可，不应简单开放任意 URL。

每次仅调用所选服务，没有静默切换或同时发送两家。明确限制输入、输出、超时和重试次数；失败如实显示，结构和引用校验不通过时拒绝采纳。重试默认 0，最多 1 次，重试仍可能计费。配置通用在线模型仅代表本地模型推理接口，**不代表数据不出本机**；当前只使用合成业务数据。后续切换本地部署模型后，可保留相同工单与知识服务接口。

## 三类核心工单

| 场景 | 业务问题 | 验证重点 |
|---|---|---|
| S1 制冷温升预警 | 制冷热点、温度上升和数据质量 | 证据质量、竞争假设、现场排查、复测与独立验收 |
| S2 UPS / 电池维护 | UPS 或电池性能退化风险 | 设备适用性、版本、维护审批、失败复测回处理 |
| S3 同负载能耗异常 | 相近工况下 HVAC 用电偏离基线 | 负载/环境可比性、优化建议、前后窗口、节能归因边界 |

容量变更作为辅助场景保留，不替代 S3。设备、告警、能耗、监控、工单等正常模块及右侧抽屉仍然可用，不强迫进入全局向导。

工单生命周期保留：待分析 → 待方案审批 → 待派单 → 待接单 → 处理中 → 待复测 → 待验收 → 已关闭。审批和派单分开；具体工程师接单、执行和记录复测；主管独立验收，管理员不能业务验收。支持失败复测、退回、取消和重开；原始证据及历史案例不被覆盖。

角色切换是演示身份，不是生产登录或服务端权限系统。工单数据仍保存在当前浏览器，知识和密钥配置保存在本机服务器，不能宣称跨设备协同或不可篡改审计。

## 本地 Markdown Wiki

遵循 [Karpathy LLM Wiki 原始构想](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 的分层思想，自行实现而非复制其内容：原始资料、编译 Markdown 页面、导航索引和追加日志分离。提供可检索/可点击的节点、实体链接、反向链接、来源、适用型号与审核状态。

内置资料全部为本项目原创合成运维知识，不冒充厂家手册。工单检索按设备族和型号筛选；不匹配时说明资料不足，不能自动套用 UPS 规程。导入资料及模型输出一律当作不可信数据；模型可提议编译或更新页面，但需人工审查后发布。知识文档见 [docs/knowledge-wiki.md](docs/knowledge-wiki.md)。

## 指标自测，不自报成绩

[评测定义与复现说明](docs/evaluation.md) 固定数据集种子、版本和哈希，记录模型、提示词版本、每例输出、错误、Token 用量及失败。模型仅接收测试输入，不接收留出期真实值或标准答案；数值基线独立运行并单独列示，绝不用基线成绩冒充模型成绩。

- R08：设备性能使用暂定的序列内合并 R² 指标（每条序列各自中心化，避免不同设备基准差异虚高），要求严格大于 0.97；正式项目的“精度”定义仍需确认。
- R09：温度使用预先规定的范围归一化 MAE，要求严格小于 5%，同时报告摄氏度 MAE，避免用摄氏温度本身作为百分比分母。
- R10：能耗使用 WAPE，要求严格小于 5%，明确零分母处理。
- R11：语义任务采用来源ID/设备族/型号/版本/拒配原因元组的精确匹配准确率，要求大于或等于 94%。

超时、格式错误、缺失结果不能从通过判定中消失；小样本烟测不能宣称完整套件通过。即使全量合成集通过，也**只证明该合成测试集**，不代表真实机房、现场节能效果或招标指标已验收。开发期间不调用付费供应商，不提供或代填用户真实 Key。

## 开发与验证

```sh
npm run check
npm install --prefix tests --ignore-scripts
npm test
```

应用运行不需要安装测试依赖。jsdom 测试依赖可能要求比应用更高的 Node 版本，详见 `tests/README.md`。离线测试使用受控假模型服务验证传输、错误与业务边界，不会自动调用 DeepSeek/Qwen。最终测试范围与未完成项见 [docs/REAL_AI_TEST_REPORT.md](docs/REAL_AI_TEST_REPORT.md)。旧版测试报告保留为历史记录，不能作为当前真实模型准确率或现场验收证明。

## 生产化前仍需完成

真实身份与服务端授权、独立业务数据库与审计存证、厂家规程授权与有效版本、现场质量契约、真实数据留出集、模型风险与安全评估、网络与设备控制隔离、容量/可靠性/国产平台实测。不要把本地角色选择、合成遥测或语言模型建议用于无人监督的电气设备处置。

### 导出测试数据与额外 Wiki 链路自测

`npm run eval:export -- --out=.runtime/exported-evaluation` 导出86例输入JSONL、独立金标、案例目录和带哈希manifest，并附10例Wiki链路输入/独立金标。金标禁止发送模型或纳入知识库。

`npm run eval:baseline` 只执行独立数值基线，不调用模型。`node evaluation/wiki-run.mjs --dry-run` 只检查真实Wiki检索；配置后可明确执行 `node evaluation/wiki-run.mjs --confirm-model-calls` 检查检索→模型→引用校验。该10例小套件与R11匹配基准分开，不证明回答事实正确性或现场94%达标。

提供商支持模式见 [兼容性说明](docs/provider-compatibility.md)，当前采用非流式JSON、Qwen显式非思考模式；并非所有自定义模型都兼容。
