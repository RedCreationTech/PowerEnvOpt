# 从监控告警到预测性维护：数据分析设计

## 1. 传统监控为什么仍不够

这里描述的是本项目要解决的典型能力缺口，不是断言所有传统厂商都缺少这些功能。

| 能力缺口 | 业务痛点 | 应有的数据分析能力 | 本原型如何验证 |
|---|---|---|---|
| 测点是孤立数值 | 温度超限不知道是负载上升、制冷故障还是传感器错误 | 资产身份、测点单位、质量、时间、供电/制冷依赖统一 | 合成资产/测点/质量与工单证据关联 |
| 只看单阈值 | 异常已发生才报警，误报和告警风暴影响值班 | 趋势、变化率、同工况残差、关联告警与预警窗口 | S1趋势与S3同负载对照，仍不宣称现场预测有效 |
| 看见相关性就归因 | 换了设定值后用电下降被误说成节能 | 负载、室外温度、运行方式和服务温度约束的可比性 | S3工单固定前后窗口和同工况约束，不用单点下降算节能 |
| 历史经验散落在文档 | 同一故障反复查找、误用不同型号/版本规程 | 可追溯、可检索、适用性严格的知识 Wiki | 原始MD→模型编译候选→人工审核→发布→双向链接 |
| 告警关闭即算解决 | 复发、失败复测和处置效果缺少学习闭环 | 原始证据不覆盖、检查/复测/独立验收、案例回写 | 同一工单编号贯穿，全程保持人工责任 |
| 模型只展示置信度 | 无法知道“准确率”对应什么样本/分母 | 冻结测试集、独立金标、对照基线、错误样本与失败统计 | R08–R11独立评测，模型不能给自己打分 |

## 2. 六层分析链

1. 数据契约层：稳定设备ID、厂家/型号/固件/资料版本、测点单位、源时间/到达时间、质量码。缺失不能补零，时钟漂移和迟到不能混成有效证据。
2. 工况层：对齐时间窗口，区分运行/待机/维护模式，保留负载、室外温度、机组启停与服务边界。相同测点在不同模式下可采用不同基线。
3. 数值分析层：先建立可独立运行的统计或机理基线，再与语言模型的数值预测比较。模型历史输入与未来留出标签分离；正式生产宜采用经过现场验证的专用预测器，不要求通用LLM代替所有时序模型。
4. 知识解释层：按资产适用性检索已审核资料，给出来源、版本、支持/反对假设、缺失证据及补测建议。语言模型用于融合文档与工单语境，不把生成文字当成测量证据。
5. 决策协同层：建议先预览，人工核验并采纳；主管审批和分派分开，执行和独立验收分开。模型不能自动更改设备或关闭工单。
6. 反馈与评估层：记录成功与失败，复测证据不覆盖原始窗口；案例先成为候选知识，经复核发布后供以后检索。线上漂移、误报、漏报、提前量和维护成本需要真实试点后持续评价。

## 3. 通用大模型与 Wiki 各负责什么

DeepSeek/Qwen 使用相同兼容接口，但每次只调用明确选择的一家。当前原型允许真实推理；开发验证使用假服务，不预先宣称任一模型达到指标。未来本地部署模型可替换传输端点，保留工单与知识接口。

Wiki 不等于向量数据库，也不等于把所有文档塞进提示词。本实现采用本地Markdown、适用性筛选和轻量文本检索，维护原始资料、编译页面、索引/日志、实体关系与来源链。它改善知识组织和可核验性，但不会自然“保证94%”。当前未训练向量嵌入模型，不能把字符串检索称为已验证的语义检索召回率。

真实LLM在给定候选资料上进行语义选择、解释和生成建议；评测区分：候选资料匹配能力、上下游检索召回能力、最终答案的来源支持程度。首期 R11 测给定候选中的适用资料匹配，不能替代端到端RAG的完整验收。

## 4. 三场景的分析证据

### S1 制冷温升

输入为窗口内的温度序列、机组状态、测点质量、工况和适用资料。比较负载上升、风路阻塞、制冷不足、传感异常等候选原因。先核验有效测点和时间，再给排查优先级；复测必须仍满足温度约束。不能仅凭一条温度趋势判断冷媒泄漏。

### S2 UPS / 电池维护

输入为设备性能/健康相关测量、负载、历史变化和厂家适用性资料。区分电池退化、接触问题、工作环境和测量问题；模型给维护建议而非剩余寿命保证。任何电气处置均需现场许可与专业人员，不由模型执行。

### S3 同负载能耗

输入为 IT 负载、HVAC 输入功率/电量、室外环境、运行模式和服务温度。先检验前后窗口可比性，估计条件基线，再将异常残差关联到可核验假设。优化后同时核对能耗、温度、负载和运行条件，不能牺牲服务温度来“达成节能”。合成12→18 kW示例只是业务演示，不是供应商实际节能效果。

## 5. 指标与试点准入

R08“预测模型精度>0.97”需要正式确定任务和统计口径；本原型先采用序列内合并R²。R09暂采用预设15–35°C运行范围归一化MAE并同时报告°C MAE，20°C只是测试协议预设，不是需求文件已批准口径。R10使用WAPE且零分母不可评估。R11使用匹配ID与适用元组完全一致的准确率；详细定义、样本分布和冻结哈希以 `evaluation.md` 和 `evaluation/manifest.json` 为准。

测试集为原创合成数据，只用于验证测评程序、模型接口与可复现实验。它不能统计证明真实机房泛化能力。进入真实试点应取得允许使用的历史数据，并按时间/站点/设备隔离训练与测试；冻结金标、基线与阈值，补置信区间、分层误差、极端工况、传感异常、漂移/域外数据、故障漏报及有效提前量，最后由独立人员验收。
