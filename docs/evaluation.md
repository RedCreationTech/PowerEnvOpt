# 独立模型验收评测

## 状态与限制

此实现是可执行的独立评测框架，不是已经达标的模型结果。开发验收仅运行了假适配器/故障注入测试，没有使用真实密钥，没有调用付费模型。仅在用户明确点击评测或执行带确认参数的 CLI 时才调用当前配置的模型。模型可能无法达到门槛，失败必须如实显示。

所有 86 个样本均为合成数据，不含实站记录，不证明生产效果。R08 的正式“性能预测准确率”定义尚待确认，当前临时使用更严格的按序列内变动计算的 R²；不能直接把 R² 解释为百分比准确率或正式验收结论。

## 冻结数据与泄漏隔离

- 数据版本：powerenv-synthetic-v2；随机种子：20261020。
- evaluation/manifest.json 提交固定 SHA-256、版本、种子和案例数。运行时重新生成并比对，任何漂移立即报错，必须人工审查并升版，不能静默更新。
- R08、R09、R10 各 12 个序列：24 个历史小时、3 小时预测窗口。序列包含不同水平、线性趋势、周期分量与确定性扰动，不是复制末值的单点样例。
- R11 共 50 个知识匹配场景：30 唯一适用、10 同等适用但内容冲突、10 无适用答案（其中 2 个缺少必要版本字段）。覆盖 UPS、HVAC、RECTIFIER、BATTERY、MONITOR 五个设备族。
- 服务端私有 evaluation/ 保存标签。模型请求只投影 case.input；不发送评测案例 ID、expected、未来观测、gold 标记或样本解释。知识匹配任务发送全部未标记候选来源 ID、设备族/型号/版本、适用症状和正文，不标出正确候选。
- 不把评测目录放入知识语料或 Wiki。服务器静态白名单必须拒绝 evaluation/、server/、tests/、.runtime/。报告含逐例答案，只由本地评测接口导出给操作者。
- 报告包括数据全集哈希、子集哈希、逐例/整体提示哈希、提示版本、请求模型、服务返回模型（缺失则 null，不用配置别名冒充）、非密钥配置哈希与用量。哈希可证明工件一致性，不证明外部模型权重或服务本身可复现。

## 预先指定指标

R08 临时门槛：within-series pooled R² > 0.97。对每个样本计算自身未来窗口均值，跨样本汇总各自 SST，再计算 1 - 总 SSE / 总 SST，避免不同设备基线差异抬高指标。SST 为零则指标无效、不能通过。逐例另报 R² 和 MAE；普通全局 pooled R² 仅作诊断，不用于门槛。服务端 runEvaluation 支持传入版本化 r08Definition.score 以替换为正式认可指标，不能通过浏览器随意更改，仍受失败案例否决约束。

R09：MAE / 20°C < 0.05，固定范围 15–35°C，等价于 MAE < 1°C。同步报告摄氏度 MAE。不除以摄氏温度值；范围在看到预测前固定，并随样本发送。

R10：WAPE = Σ|预测 - 实际| / Σ|实际| < 0.05。实际值为零的单点仍保留误差，全集分母为零时无效、不能通过，不采用任意 epsilon 美化分母。

R11：完全正确的知识匹配元组数 / 所有选定语义案例数 >= 0.94。输出必须包含 sourceId、family、model、version、reasonCode，五个字段全部正确才算成功。唯一匹配 reasonCode=match；无匹配/缺少关键元数据为 no_match；同等适用且正文互相矛盾为 ambiguous。后两者四个身份字段必须全为 null。不是故障分类准确率。

全部门槛使用未四舍五入数值：0.97 不通过 R08；0.05 不通过 R09/R10；0.94 通过 R11 数值门槛。超时、格式错误、缺失字段、未知来源/无效元组、非有限数字和错误预测长度均保留为失败案例，使对应任务的最终 gate 失败。数值指标只对有效预测计算，但同时报告 totalCases、validCases、failedCases、coverage，绝不把失败样本当成不存在。语义准确率直接保留总分母。

## 独立基线

数值基线是尾部 6 点普通最小二乘线性外推，并加上与模型相同的显式已知干预量，独立计算并独立展示。它不用未来值，也不是模型调用的替代、降级或成功兜底。模型失败时 prediction=null，不能写入基线预测冒充模型输出。语义任务没有假造的模型替代基线。

## 执行

先按配置文档设置服务端模型。浏览器选择 Smoke 或 Full 后，显式点击运行：

- POST /api/evaluation/run，JSON {"scope":"smoke"} 或 {"scope":"full"}，需要同源 CSRF 标记。
- GET /api/evaluation/status?id=任务ID 返回进度和指标。
- GET /api/evaluation/export?id=任务ID 返回完整 JSON 证据。
- POST /api/evaluation/cancel，JSON {"id":"任务ID"}：设置取消标记，在途请求按超时结束后不再启动调用，其余案例保留并标记 CANCELLED，最终状态 cancelled，不能通过验收。
- 同时只允许一个任务。一次执行最多 86 个案例，每例 max_tokens=500，遵守服务端超时和重试设置。总预算窗口默认 15 分钟；已在途调用按其传输超时退出，未启动案例标记 TIMEOUT，绝不漏掉。
- Smoke 使用 11 例：每个数值任务 2 例、知识匹配 5 例（3 唯一、1 冲突、1 无匹配）。即使全对也只表示连通性/格式覆盖，fullSuitePass 永远为 false。
- Full 使用全部 86 例。全部门槛通过仍仅为合成测试门槛通过，productionValidated 永远为 false，正式 R08 定义未确认时明确保留 pending。

CLI（会调用已配置的真实服务，请先检查费用）：

    node evaluation/run.mjs --confirm-model-calls --full --out=.runtime/my-report.json

不加 --full 只运行 Smoke；没有 --confirm-model-calls 时拒绝运行。API 报告原子保存到 .runtime/evaluations/，目录权限 0700、文件 0600，进程重启后可继续读取已完成审计报告。密钥不进入报告。进程在执行中退出时不会声称已完成，未完成的内存任务不会被恢复为成功。

## 无网络自动验证

    node --test tests/evaluation.test.mjs

覆盖数据冻结、严格输入投影、未来值不泄漏、门槛边界、常量目标、零能耗分母、非有限/长度错误、超时、独立基线、失败分母、Smoke 限制、单任务锁和持久化恢复。测试中的 oracle 假适配器只用于证明评分代码工作，绝不能当作真实模型性能报告。测试写到临时目录，不污染真实评测历史。

|任务|正常|退化|工况变化|分布外|传感器异常|合计|
|---|---:|---:|---:|---:|---:|---:|
|R08 性能|4|3|2|1|2|12|
|R09 温度|4|3|2|1|2|12|
|R10 能耗|4|3|2|1|2|12|

正常含趋势/周期扰动；退化增加非线性变化；工况变化通过明确已知的下一窗口加性变化模拟负载/天气变化，变化量是事前输入而非未来测量值，这是人工已知干预，不代表未知工况突变可被预测；分布外含不同基线；传感器异常保留历史尖峰并明确 suspect，不删除样本。当前这些是有意可控的合成情景，不声称覆盖真实天气物理过程、传感器所有故障形态或实际工况分布。

|R11 知识匹配|数量|干扰和判定|
|---|---:|---|
|唯一适用来源|30|同型号/版本但语义主题错误的候选；旧版本；错误型号/设备族|
|冲突/歧义|10|两条同样适用的已批准正文对隔离操作给出相反指示，须返回 ambiguous|

请求使用中文症状和否定条件；候选适用描述使用英文改写，元数据一致仍须理解“能否启动、温度是否超限、输出是否波动”。候选顺序固定轮转，来源 ID 为不含 current/draft 等角色提示的确定性不透明哈希。全部候选和请求均为合成设计，尚无独立专家标注、实站分布抽样或置信区间结论；不得把 50 例的小样本准确率泛化为生产 94%。

## 已执行的独立基线（零模型调用）

复现：

    node evaluation/run.mjs --baseline-only --out=.runtime/baseline-report.json

提交的 evaluation/baseline-reference.json 是真实运行的数值基线结果，不是 LLM 结果，不表示模型已通过测试：

- R08 within-series pooled R² = -46.38795477561644，不通过。普通全局 R² = 0.982553358665524，但它被设备间基线差异抬高，因此不用于门槛。
- R09 MAE = 0.727305621693123°C；固定范围归一化误差 = 0.03636528108465615，通过该合成基线门槛（不是模型结果）。
- R10 WAPE = 0.03441983204823895，通过该合成基线门槛（不是模型结果）。
- R11 无数值基线，真实模型尚未测试。

基线报告包含每场景分层指标、逐例预期/预测及数据哈希。所有失败原样保留，没有为了达标调整门槛。正式模型评测必须另外由用户显式启动。

## 单独的真实 Wiki 链路自测（不是 R11 门槛）

新增 evaluation/wiki-run.mjs，使用实际 WikiStore.retrieve → 当前模型适配器 invokeModel → validateResult 引用校验 → 来源集合指标。10 个冻结原创问题覆盖实际种子页 cooling-evidence、energy-baseline、battery-evidence，并包括未知型号、过期版本、设备族/型号不匹配及未知设备族。期望来源 ID 只保存在服务端评分数据，不传给模型；模型只收到真实检索候选与问题。

仅检索检查（不调用模型）：

    node evaluation/wiki-run.mjs --dry-run --out=.runtime/wiki-retrieval.json

完整链路（会调用当前已配置模型，须操作者显式确认）：

    node evaluation/wiki-run.mjs --confirm-model-calls --out=.runtime/wiki-e2e.json

报告记录固定问题集哈希、当次实际 Wiki 全量内容/元数据快照哈希、逐例输入哈希、检索来源、期望来源、模型引用、请求模型及服务返回模型。来源集合精确匹配、宏平均引用 precision/recall 的分母保留所有案例；调用/引用校验失败计零，不跳过。正确无匹配且零引用为正确拒答来源集合；有预期却零引用为失败。引用全部属于检索集合仍可能引用了无关页面，因此必须另评分与预期来源的匹配。

已实际运行的是 dry-run：10 个检索检查中，6 个正常问题都检索覆盖预期页面，4 个不适用元数据问题都返回空集合；零模型调用。实际 Wiki 快照哈希为 625cc5eafa81f8bfd653d0724d31a3897e2f4325f171c91485d24f0a62fbc1a4，证据见 evaluation/wiki-retrieval-reference.json。检索会保留若干同设备候选，覆盖预期不等于候选全相关。没有真实模型答案或引用质量结果，模型指标为 null。

    node --test tests/wiki-evaluation.test.mjs

5 个测试使用实际 WikiStore 和假模型，覆盖无答案泄漏、未知引用拒绝、超时保留分母、服务未报告模型身份时保留 null。该小样本管线自测独立于 R11 的 50 个匹配题与 94% 门槛，更不检验回答逐句事实有效性、维修安全性或生产适用性。

## 独立导出与复用

执行 `npm run eval:export -- --out=.runtime/exported-evaluation`，得到输入与金标分离的JSONL、案例目录JSON/CSV、文件与提示词哈希manifest。另附10例实际Wiki链路的独立输入和金标。不要将gold文件或整个目录发送给模型。
