# v5 实现边界与验收追踪

## 数据边界

浏览器保留合成设备与工单状态，Node 本机后端负责模型配置、同源 API、知识读写和独立评测。真实在线模型接收用户主动提交的合成工单片段、选定知识资料或无答案的评测输入。供应商凭据仅存在本地服务器运行配置和请求 Authorization 头，不进入提示词。

这不是生产级权限系统。界面的六人/五岗位检查用于验证业务职责分离，不应被视为登录、身份认证或不可抵赖审计。后端配置与 Wiki 维护属于单一本机使用者，而非按前端角色隔离的多租户接口。

## 层次与责任

- `app.js`：既有资产、遥测、列表和模块。
- `workflows.js`：岗位协同、场景模板、工单状态、审批/分派/复测/独立验收、右侧详情。
- `ai-ui.js`：真实模型设置、主动调用、人工采纳、Wiki 浏览/导入/候选审核、自测入口。
- `server.mjs`：回环 HTTP、同源/CSRF、输入限制、静态资源白名单和 API 路由。
- `server/config.mjs`：提供商与端点校验、密钥保管/脱敏、限制权限写入。
- `server/ai.mjs`：OpenAI 兼容传输、超时/重试/输出限制、结构与引用 ID 校验。
- `server/wiki.mjs` 与 `knowledge/`：原始资料、审核知识、可解析链接和来源、检索、候选/人工审核/发布。
- `server/evaluation.mjs` 与 `evaluation/`：冻结合成数据、独立基线、真实模型推理评测、逐例结果与报告。

## 关键守卫

| 风险 | 控制 | 仍存在的边界 |
|---|---|---|
| 把数据内容当指令 | 固定系统提示把工单/Markdown当不可信资料，结构化输出白名单，无工具执行 | 无法形式化保证模型不受提示注入影响；因此需人工复核 |
| 错引资料 | 设备族/型号适用性筛选与引用 ID 校验，未知型号不自动套 UPS | ID 有效不等于观点被资料充分支持，人工审核仍必需 |
| 输出 XSS | 文本转义，Markdown 不执行 HTML，页面资源受限 | 页面仍有既有内联事件，为兼容设置允许内联脚本；不能把本机服务开放公网 |
| 密钥外泄 | 只在服务器保存、配置脱敏、供应商域名限制、端点改变清除旧密钥、禁止重定向 | 本机恶意软件或有文件读取权限的人不属于此原型防护边界 |
| 跨站写入 | Host/Origin 校验与会话 CSRF 令牌，无跨域许可 | 无用户认证，不适合多人服务器 |
| 模型控制流程 | 模型只产出候选，人工采纳不推进审批/关闭，职责与复测守卫保留 | 前端本地状态可被本机用户修改，生产需服务端领域授权 |
| 假验收/答案泄露 | 金标与输入分离、冻结哈希、失败不丢弃、烟测/全量区分、独立基线另列 | 合成集不能证明现场泛化、真实节能或招标达标 |

## 场景追踪

| 用户要求 | 代码/操作路径 | 可验收证据 |
|---|---|---|
| 不推倒既有页面 | 模块导航 + 右抽屉 | 既有 DOM/角色/工单测试继续运行 |
| S1 制冷异常 | 制冷类工单、证据、知识、诊断、审批、复测 | 合成原始窗口与复测记录不同，独立验收 |
| S2 UPS/电池维护 | 电池维护工单与设备适用资料 | 关联型号/版本、失败复测回处理、不适用拒配 |
| S3 同负载能耗异常 | HVAC 能耗工单与优化验证 | 对照负载/环境/前后窗口，不把任意功率下降叫节能 |
| 双在线模型与未来本地替换 | 设置所选 provider + API/模型/端点 | 假服务传输验证；真实提供商成功由用户配置后验证 |
| Wiki 不是硬编码图 | Markdown 导入、编译候选、审核/发布、图节点/链接 | 来源哈希、适用性、可打开原始资料、反向链接 |
| AI 指标自证 | 烟测/全量固定集、实际所选模型、独立基线、导出 | 每例输出/错误/失败/用量与完整元数据 |

## 已知设计取舍

没有接入真实设备，也不生成可直接执行的设备控制指令。后端不做静默提供商切换。固定规则演示仍保留且明确标识，不能把其文字称为真实 AI 结果。真实 AI 业务输出的语义正确性、两家供应商当前账号权限/计费、真实模型指标以及现场测试均需用户配置并运行后确认。
