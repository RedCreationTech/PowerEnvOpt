# v4 四阶段 AI 辅助决策：独立回归记录

测试日期：2026-10-17。测试对象为 workflows.js / styles.css 的增量增强。

## 结果

更新后完整 npm test 退出码为 0：23 主业务 + 7 额外 + 5 数值一致性 + 114 内容区按钮冒烟 + 7 服务器处理器 + 24 关联流程 + 19 岗位/抽屉 + 11 新增四阶段，共 210 项检查/分组全部通过。按钮冒烟是单次点击检查，不能等同于 114 个完整业务流程。

## 测试范围

新增 tests/ai-story.cjs，覆盖 11 组 DOM/逻辑检查：

- 三个事件的四阶段状态与唯一当前步骤，确认、诊断、人工审批、工程执行、复测、独立验收依次推进。
- 方案比较中选择第二方案，由主管批准并分派赵工，选择进入审批记录及工单；刷新后保持。
- 未被分派的工程师不能接单；三类事件的完整证据、诊断、决策、工单、复测、案例编号可追溯。
- 每类事件展示三项假设及知识与事实映射，明确合成样本、历史快照、非真实模型与因果边界。
- 缺失输入阻断预测与诊断；质量恢复后旧诊断仍不能审批或展示有效风险外推，重新诊断后恢复。
- 主管退回重新诊断、失败复测返回排查、检查项清空、成功复测被主管退回，均不提前生成案例。
- 已关闭事件不再展示处置前预测正文作为当前风险。
- 所有角色可见页面仍可加载，抽屉不改变模块标题、四阶段导航不会重复插入。

## 运行方法与边界

正常复现：在 tests 目录按其 README 安装 jsdom 后执行 npm test。
本次使用环境中已存在的 jsdom 30.1.3，通过 NODE_PATH 指向原 QA 依赖目录运行，未新增安装或修改运行时依赖。

上述为 jsdom 的 DOM、事件处理和共享状态验证，未进行真实浏览器视觉、响应式排版、点击命中区、屏幕阅读器、实际文件保存或设备接入验收。既有被限制的浏览器路径未重试或绕过。应用仍为本地固定数据与规则模拟，不证明真实 AI 效果或生产安全。

结果见 tests/ai-story-results.json；既有测试记录见其他 tests/*results.json。每次复现覆盖相应结果文件。
